## 해석 한계

- 기대값과 서버를 같은 사람(김태형)이 같은 README 명세로 작성했다. 21/21 pass는 서버가 **그 명세와 일치함**을 뜻하며, 명세 자체가 독립적으로 옳다는 증거는 아니다.
- 음성 대조군은 평가기가 틀린 기대값을 잡는지만 확인한다. 일부러 바꾼 한 케이스만 실패했다.
- PCAP은 정상 5세션만 담는다. 오류 코드는 바이너리에만 있다.
- REA 단독 분석은 바이너리 개요(`binary_overview`) 근거를 만든 것이다. 명령이나 프로토콜을 복원했다고 주장하지 않는다. 모델 요약과 원본 근거의 대조는 아직 하지 않았다(N05 전체 연동 대기와 같다).
- 호스트는 Mac arm64이고 실행은 amd64 에뮬레이션이다. 2026-11-09 정의종의 Windows x86-64 호스트 Docker에서 AI가 다시 빌드해 서버·클라이언트 해시가 일치했다([통합 재현 기록](N05-N07-integration-2026-11-09.md)). 정의종 본인 확인은 아니다.
- 본인 확인: 2026-11-09 김태형이 Mac Docker Desktop에서 한 컨테이너로 서버·원본 클라이언트를 실행해 서버 배너와 `sum=6`을 직접 확인했다. 캡처·평가·REA 결과는 AI 실행 기록이다.

## 재실행

저장소 루트에서 실행한다. 바이너리 빌드와 이미지 빌드는 [연습 자료 README](../../practice/n06/README.md)의 명령을 따른다.

```sh
tag=$(date +%Y%m%d-%H%M%S)
docker compose -f compose.n05.yaml run --rm n05 gcc -O0 -fno-inline -Wall -Wextra -o runs/n06/practice-server practice/n06/server.c
docker compose -f compose.n05.yaml run --rm n05 gcc -O0 -fno-inline -Wall -Wextra -o runs/n06/practice-client practice/n06/client.c
docker compose -f compose.n06.yaml run --rm n06 python3 scripts/n06-capture.py runs/n06/practice-server runs/n06/practice-client runs/n06/capture-$tag.json
docker compose -f compose.n05.yaml run --rm n05 python3 scripts/n07-evaluate.py --cases practice/n06/cases.json --binary runs/n06/practice-server --out runs/n06/eval-$tag.json
docker compose -f compose.n05.yaml run --rm n05 node scripts/rea-smoke.mjs --rea-only runs/n06/practice-server runs/n06/rea-$tag.json
```

기대 결과: 캡처 `success: true`, 패킷 50, SYN 5, FIN 10. 평가 `pass 21`, 종료 코드 0. REA `success: true`이고 `doctor.healthy: true`. 같은 이미지·플랫폼·소스에서 재빌드하면 바이너리 해시가 같았다(AI가 2026-11-08 클린 clone `2844a05`에서 서버·클라이언트를 재빌드해 1회 확인). PCAP 해시는 실행마다 다르다. 2026-11-09 정의종의 Windows x86-64 호스트 Docker에서 AI가 다시 빌드해 서버·클라이언트 해시가 일치했다([통합 재현 기록](N05-N07-integration-2026-11-09.md)). 정의종 본인 확인은 아니다.
